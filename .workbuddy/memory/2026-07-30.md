# 2026-07-30 工作日志

## Zabbix Desktop Info 项目构建

用 C + Win32 + GDI+ + UpdateLayeredWindow 实现了 Zabbix 桌面实时监控仪表盘程序。

### 完成内容
- 自实现轻量级 JSON 解析器 (json.h/json.c)
- Zabbix JSON-RPC API 客户端，使用 WinINet (zabbix_api.h/zabbix_api.c)
  - 支持 user.login, host.get, item.get, history.get
  - 兼容 Zabbix 5.4+ (username) 和旧版 (user)
- 配置管理模块，JSON 格式存储到 %APPDATA%\ZabbixDesktopInfo\config.json
- GDI+ 渲染模块 (render.h/render.cpp)，三种图形：
  - 仪表盘：270度弧形指针，支持阈值变色(绿/黄/红)
  - 卡片：圆角矩形+标题+数值
  - 趋势图：折线图+坐标轴+渐变填充
- Widget 透明窗口管理 (widget.h/widget.c)：
  - UpdateLayeredWindow + 32bit premultiplied ARGB DIB
  - 支持置顶、拖拽、点击穿透、右键菜单
  - 后台线程定时刷新数据
  - 配置对话框（刷新间隔/透明度/颜色/阈值）
- GUI 界面：
  - 登录对话框 (ui_login.h/ui_login.c)
  - 监控项选择对话框，主机列表→监控项列表→选择类型 (ui_select.h/ui_select.c)
- 主程序入口 (main.c)：系统托盘+消息循环+widget 管理

### 技术要点
- MinGW GCC 6.3.0 编译，C 文件用 gcc，GDI+ 渲染文件用 g++
- 需要 -D_WIN32_WINNT=0x0600 -DWINVER=0x0600 -D_WIN32_IE=0x0600
- GDI+ 的 FillEllipse/AddLine 有 REAL/INT 重载歧义，需要显式 cast
- JSON 内存管理：json_object_set/json_array_push 采取浅拷贝+free 容器的方式，调用后不要再 free 传入的 value
- UpdateLayeredWindow 需要 premultiplied alpha，GDI+ 绘制后需手动 premultiply

### Bug 修复：主机列表乱码 + 点击崩溃
- 根因1：json_free 对数组内部元素调用 free(v)，这些元素是父数组 malloc 连续块的一部分，不能单独 free → 堆损坏 → 崩溃
  - 修复：拆分为 json_free_contents（只释放内容不 free 结构体）+ free(v)（释放根节点）
  - 同时修复 json_object_set 中对旧值调用 json_free 的相同问题
- 根因2：Zabbix API 返回 UTF-8 中文，ANSI ListBox 用 SendMessageA 传 UTF-8 字节 → 乱码
  - 修复：添加 utf8_to_wide + SendMessageW 添加列表项
  - 搜索框改用 GetWindowTextW + Unicode 子串搜索
  - 状态文本添加 set_text_utf8 helper（UTF-8→UTF-16→SetWindowTextW）
- 根因3：api_call 的 static int rpc_id 非线程安全（工作线程并发访问）
  - 修复：改为 volatile LONG + InterlockedIncrement
- 根因4：点击主机后 WaitForSingleObject(item_thread, 2000) 卡 UI，且快速点击会覆盖 FetchParams
  - 修复：去掉阻塞等待，添加 items_loading 标志 + 禁用主机列表防止并发
  - fetch_items_thread 改用 FetchParams.host_id_buf 内嵌缓冲区（安全副本）
- 改进：Zabbix API 的 hostids/itemids 改为数组传参（兼容性更好）

### Bug 修复：点击"添加组件"后崩溃（config_save double-free）
- 根因：config_save() 中 json_array_push(jw) 和 json_object_set(widgets_arr) 后又分别调用了 json_free(jw) 和 json_free(widgets_arr)
  - json_array_push/json_object_set 是 move 语义：浅拷贝 *val 进容器后 free(val)
  - 之后再 json_free 就是双重释放 → 堆损坏 → 崩溃
  - 修复：删除 config_save 中对已消费的 jw 和 widgets_arr 的 json_free 调用
- 教训：json_array_push 和 json_object_set 消费所有权后，调用方不应再释放该值

### 新增功能：密码 DPAPI 加密存储
- 问题：配置文件 config.json 中密码以明文存储，存在泄露风险
- 用户要求：使用无法解密的加密方式
- 技术说明：Zabbix user.login API 要求传入明文密码，真正的单向哈希（SHA-256 等）不可行
  → 改用 Windows DPAPI (CryptProtectData/CryptUnprotectData)
  → 密码用当前 Windows 用户凭据加密，配置文件中存 hex 编码的密文（enc: 前缀）
  → 只有同一 Windows 用户在同一机器才能解密，拷到别处无法解密
- 实现：config.c 新增 hex_encode/hex_decode/dpapi_encrypt/dpapi_decrypt 函数
  - config_save：保存时加密密码，加 "enc:" 前缀标记
  - config_load：读取时判断 enc: 前缀，解密；旧明文格式向后兼容
  - build.bat 新增 -lcrypt32 链接
- 已有配置自动迁移：首次加载按旧明文处理，下次保存自动加密
